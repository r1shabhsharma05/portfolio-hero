Stop Paying for AI Videos: Make Them Free on Your Own GPU with FreeVideo

The reel says stop paying for AI videos — this is the tool behind it. FreeVideo runs the MiniMax H3 video model on your own computer, free, from 8 GB of VRAM. Here is how to install it, make your first video, and the agent skill that drives it.

"Stop paying for AI videos. This tool..." — that is the hook of the reel on this page, and the tool is FreeVideo, an open-source project by FlashML-org. It runs a real AI video model on the computer you already own, so a generation costs you electricity, not credits. Here is the full breakdown: what it is, how to install it, how to make your first video, and the agent skill that can drive it for you.

What FreeVideo actually is

FreeVideo is a local inference engine for MiniMax H3, a text-to-video model, rebuilt to run on consumer GPUs. The headline number: it runs in as little as 8 GB of VRAM and 16 GB of RAM — a normal gaming laptop, not a datacenter. It adapts to your hardware automatically: weight format (int8 on GeForce and RTX 30-series cards, FP8 on workstation cards), weight streaming and chunked computation to keep memory low, and whichever attention kernels your GPU supports.

It runs as a ComfyUI plugin with launchers for Windows, macOS and Linux, and it takes more than text prompts: first and last frames, plus image, video and audio references. There are four quality levels (Light, Medium, High, Max), videos can run over a minute long, and the newer H3 Image mode makes pictures up to 16 MP locally.

Step 1 — Install it (one click)

  1. Download the launcher for your system from the FreeVideo GitHub repo — FreeVideo.exe on Windows, a .dmg on macOS (Apple silicon), an AppImage on Linux.
  2. Run it and pick an existing ComfyUI folder, or let it install a fresh one. Existing model folders are reused; anything missing downloads automatically.
  3. Click Install & launch. ComfyUI opens in your browser with the FreeVideo workspace ready.

That is the whole setup. No API keys, no subscriptions, no per-video billing — the model lives on your disk.

Step 2 — Make your first video

  • Write a prompt. Describe the shot: subject, action, camera, mood. Short and concrete beats long and poetic.
  • Pick a quality level. Light for quick drafts, Max when the shot matters. Higher levels look better and take longer — that is the only trade-off.
  • Preview first. FreeVideo can render a half-resolution preview before the full finish, so you only spend GPU time completing videos you actually like.
  • Start or end on a picture. Generate a still first (H3 Image), then pass it as the first or last frame and let the model animate between them.

Your finished videos carry their workflow inside them — drop one back onto the ComfyUI canvas later and its prompt, seed and settings come back with it.

Step 3 — Push it further

  • References: feed an image, a video or an audio clip as a reference to steer style, character or motion.
  • Community LoRAs: MiniMax H3 LoRAs plug straight into the workflow for specific styles.
  • Batch generation: queue several shots at once and join them in order.
  • Timeline editing: the editing view lets you cut generated clips on a timeline inside the same workspace.
  • Minute-long videos: long jobs are automatically split into parts and joined, so length is a patience question, not a hard wall.

Copy the skill

FreeVideo ships with an agent skill — a SKILL.md that teaches an AI agent (Claude Code, Codex, Cursor, Gemini CLI) to drive FreeVideo through its MCP tools: check status, read the prompt guide, plan the job with a time estimate, generate, and look at the result before reporting it. Copy it below, or grab it from the repo.

---
name: freevideo
description: Make videos and pictures with the user's local FreeVideo through its MCP tools or the `freevideo agent` command line. Use when the user asks to generate or continue a video, make or edit a picture, cut a timeline or make a multi-shot film in FreeVideo.
---

# FreeVideo

FreeVideo runs on the user's own computer. Everything below goes through its MCP server (tools named `freevideo_*`) or the same operations from a shell: `./freevideo agent <command>` (Windows: `freevideo.cmd agent`).

## Before anything else

1. Call `freevideo_status`. If it is not ready, tell the user what is missing; do not retry in a loop.
2. Before writing a video prompt, read `freevideo_prompt_guide` once (not needed for a picture alone). Prompts are English sections; dialogue and on-screen text stay in the user's language.
3. Before a video, call `freevideo_plan` with the job you intend to run (it plans videos only). It returns the real frame count, the number of parts and a time estimate for this computer. Tell the user the estimate before a long run.
4. The user sees the same work in the FreeVideo window. A tool may answer `needs_confirmation`: wait for the user (`freevideo_wait` without an id), then repeat the identical call once approved. If the user declines, stop and say so; do not retry with a changed reference.

## Pick the right task

- Only a picture asked for (a drawing, a poster, a character, a scene, no motion): one `freevideo_generate_image` call and stop. No video prompt guide, no plan, no video job; report where the picture is. Several pictures are several calls, or one `freevideo_submit_batch`.
- One video, up to 60 seconds: `freevideo_generate`. Longer than the device can do in one run is cut into parts and joined automatically. The device limit is a hard cap, not a target: aim for 15 to 20 seconds per generation.
- Start from or end on a picture: pass it as first or last frame. Make the picture first with `freevideo_generate_image`.
- A story, scene or short drama: follow "Making a short drama" below. Several shots to choose between: the `freevideo_drama_*` tools; see `references/film.md`.
- Existing footage on a timeline: the editing project tools. See `references/edit.md`.
- A picture to change: `freevideo_edit_image` for a quick change, the `freevideo_image_*` tools for layered edits. See `references/image.md`.
- Several independent jobs, or storyboard shots that do not depend on each other: put all of them in a single `freevideo_submit_batch` call, one job per shot with its own `ref`, then join the results in order. A shot that starts from the previous shot's last frame waits until that shot is done. Shots cut inside one generation with `[Shot N]` markers are one job.
- What this computer can make: read the limits from `freevideo_capabilities` and report them as given (maximum width and height, shortest and longest seconds, frame rate). Do not answer from memory or round them.

## Making a short drama

Step one is the story, before any generation: a one-page outline with the lead's goal, the opponent's moves, the escalation, the low point, the reversal and the ending, each beat causing the next. The user confirms it; only then write dialogue and generate. Famous scenes may decorate a story, never replace it.

One generation or several shots (the recommended length decides, not the device cap; `freevideo_capabilities` reports the cap as given):
1. One `freevideo_generate` with `[Shot N]` cuts inside it (four to six cuts) when the whole piece is about 20 seconds or less, stays in one place, has at most three speakers and needs no shot to be chosen or reshot separately.
2. Otherwise the `freevideo_drama_*` tools, even when this computer can make 60 seconds in one run. Each shot is one generation of 15 to 20 seconds, cut inside with `[Shot N]`; a shot with a cast card or reference pictures is at most 15 seconds, and longer content goes into the next shot with continue=true; a plan that is refused for length is shortened to that limit, never forced; never write 3 to 6 second shots. When the computer's limit is below 15 seconds, use that limit. A continuous action across two beats (a kick and its catch, a handover) stays in the same shot. Move from shot to shot through the story (someone arrives, looks, answers), not by forcing the last frame onto the next shot. Independent shots go in one batch; a shot that continues the previous one waits for it.
3. When unsure, choose the drama tools.

The short version, for every model (a small model can rely on point 7 alone): (1) story outline first; (2) about 20 seconds or less in one place with up to three people is one generation, longer is the drama tools; (3) cuts of 2 to 4 seconds in `[Shot N]`; (4) six sections in order: `subject_definitions:`, `summary:`, `retention_analysis:`, `detailed_description:`, `overall_soundscape:`, `non_diegetic_music:`; (5) people tagged `<Subject N>` with speakers numbered (S1), (S2) by first spoken line in that video; (6) say what is there and keep negation words out; (7) with the `freevideo_drama_*` tools, fill the structure fields (characters, `outline`, `blocking`, `continuity`, and per shot its `scene` and the cuts with `at`, `framing`, `action`, `camera`, `lines`) and leave `prompt` empty: the tool writes the six sections and the (S#) numbers itself; (8) the full example and the rest are in `references/film-script.md`.

Before each generation: one card per person (`freevideo_cast_list` first), clothes fixed for the whole film, a seating or standing plan for every beat, only what is seen and heard in the prompt (say what is there, never what is not), dialogue word for word, speaker numbers by order of first line in the video. Rules and examples for each of these, and the five faults to check before generating (stray lettering, small faces in wide shots, text under 14 pixels, third-party marks, voice references), are in `references/film-script.md`; the rest of the checks are in `references/film.md`. Generate two seeds of the first shot, look at them at full size, and only then continue. Whoever makes a shot looks at every take before choosing it.

## Running jobs

- A job takes minutes. Call `freevideo_wait` with the job id; it returns after at most 25 seconds. If the job is still active, call it again with the same id. Never submit the same job twice.
- A failed or interrupted generation is continued with `freevideo_resume`; only unfinished parts run. When a generation fails with `retryable` true, resume it once yourself; if it fails again, tell the user what happened.
- An `invalid_request` about size or length lists what is allowed. Resubmit once with the legal value nearest to what the user asked for (on a tie, the smaller one) and change nothing else; then tell the user which size was used.
- `freevideo_cancel` only for a job you started and the user wants stopped.
- Look at a result before reporting it: `freevideo_look` (a frame or a contact sheet).
- Report what you made with the saved-video id (`freevideo_library`), not a local path.

## Rules

- Do not start a second generation while one for the same request is running; the computer has one GPU.
- Never claim a video is good without looking at it.
- Keep your own chat short; the user is watching progress in FreeVideo.

How the skill works

The skill is a strict little operating manual. Its flow, in order:

  1. Check before anything. freevideo_status first — if the engine is not ready, the agent reports what is missing instead of retrying in a loop.
  2. Read the prompt guide once. Video prompts are written in English sections; dialogue and on-screen text stay in your language.
  3. Plan before generating. freevideo_plan returns the real frame count, the number of parts and a time estimate for your machine — you hear the estimate before a long run starts.
  4. Pick the right task. A picture is one image call. One video up to 60 seconds is one generation (aim 15–20 seconds per generation, the device cap is a ceiling, not a target). A story becomes a short-drama flow: outline first, your confirmation, then shots.
  5. Run jobs properly. Wait on the job id, never submit twice, resume failed generations instead of restarting, and always look at the result (freevideo_look) before claiming it is good.

The rules at the end are the whole philosophy in three lines: one GPU means one generation at a time, never claim a video is good without looking at it, and keep the chat short — you are watching progress in FreeVideo itself.

Why this works

Paid AI video tools charge per generation because the GPU is theirs. FreeVideo moves the GPU to your desk: the model is open, the engine is open, and the only cost left is time. That changes how you work — you can afford ten drafts of a shot, a preview pass before every finish, and a skill-driven agent that plans, generates and checks while you watch. The reel's claim is simple because the math is simple: stop renting the GPU, and the videos stop costing money.
