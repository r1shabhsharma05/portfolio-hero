How I Made a Trending Song's Lyric Video with AI

Kalyani is a released song by ARJN × KDS × Fifty4 × Ronn ft. Shreya Ghoshal. I didn't make the song — I made its lyric video with AI tools and code. Here's the exact pipeline, step by step.

First, the correction — because this post would be wrong without it.

First, the correction

I did not make the song. Kalyani is an already-released song by ARJN × KDS × Fifty4 × Ronn ft. Shreya Ghoshal. What I made is the song's lyric video / visualizer — with AI tools and code.

So there is no "prompt that made the song". There is no single magic prompt for the video either — it was a proper code pipeline, and this post is that pipeline, exactly as it happened. The video on this page is the result: the Kalyani lyric video, 54.68 seconds, 1920×1080 at 60fps.

The tools

Every tool is free and open-source, and everything ran locally.

Tool What it did
Demucs (htdemucs model) Separated the vocals from the song (vocal stem + no-vocals stem), so the timing analysis ran on clean vocals
faster-whisper (large-v3 model) Transcribed the vocals and gave every word an exact start and end time (word-level timestamps). WhisperX was tried first — its install failed, so faster-whisper was the fallback
librosa Detected the song's tempo, beat grid and kick-drum hits
HyperFrames (HTML/CSS/GSAP + headless Chrome) Built the whole video as a web composition and rendered it frame by frame into an MP4
Python + Pillow Converted both photos into particle data
FFmpeg / ffprobe Verified the final video (duration, resolution, sync checks)
Editor (AI agent) Ran the whole pipeline, fixed the errors, verified every stage

The exact steps

  1. Inputs collected. The song MP3 (a 54.67 sec clip), the lyrics — 18 lines / 88 words, drafted by reading the reference video's frames and confirmed by bubu — 2 photos (one of the artists, one traditional portrait), and the Spotify logo.
  2. Environment setup. A Python venv, then Demucs, librosa and faster-whisper installed. Two install failures had to be fixed first — a torch version pin and a PyAV pin (av==12.3.0).
  3. Vocal separation. Demucs split the song and gave back vocals.wav.
  4. Word alignment. faster-whisper large-v3 (CPU, int8) ran on the vocals and returned a timestamp for every word. The heard words were then fuzzy-matched against the real lyrics and corrected — so the video always shows the correct lyrics, while the timings come from the machine.
  5. A bug caught and fixed. The first pass missed the sung (melodic) female section — only 48 words came back. A second pass on the full mix (92 words) plus segment-locked positional mapping produced the final timings, cross-checked between both methods at ~0.1 sec agreement before it passed.
  6. Beats and kicks. librosa found tempo 129.2 BPM, 118 beats, 77 kick hits.
  7. Section map. The song was split into 4 looks — Lines 1–4: Spotify Card look · Lines 5–12: Particle Portrait (the photo morphs at line 9) · Lines 13–14: Card reprise · Lines 15–17: Gold Motion Graphics · Line 18: Rain Player ending.
  8. Particle sampling. Both photos were grayscale-sampled into 6,000 matched particles, so photo 1 can morph into photo 2.
  9. Composition generated. A Python script (gen.py) built the full 1920×1080 HTML composition from the analysis data — 159 animation tweens, and not one lyric timing typed by hand. Everything is data-driven.
  10. Checks and snapshots. The HyperFrames checker found 2 errors (overlay visibility + content overlap) — both fixed. The snapshots found a whitespace bug (the flex layout was eating spaces) — also fixed.
  11. Render. Frame by frame at 60fps — 3,280 frames, 13 min 14 sec.
  12. Verify. Frames were pulled out of the rendered file and word sync was checked at 4 timestamps — 2.5s, 21s, 36s, 51s — all pass.
  13. Deliver. Final MP4 — 1920×1080, 60fps, 54.68 sec, audio = the original song MP3, untouched. Posting was not mine — the file was delivered to bubu.

Settings

  • Language (alignment): Hindi (--lang hi) — the song is a Malayalam rap + Hindi singing mix, and the lyrics were given in Romanised text
  • Whisper model: large-v3, CPU, int8 compute
  • Tempo: 129.2 BPM — detected from the song, not a setting
  • Video: 1920×1080 (16:9), 60fps, H.264
  • Spotify card: 3D tilt rotateX(5°) rotateY(−10°) rotateZ(−3°), red gradient #f43a4d → #8f0a22
  • Gold lyrics: Playfair Display italic, gold gradient #fae7a8 → #b9891f, ~120ms blur transition on word change
  • Particles: 6,000 · 7 glow sparks on every sung word · particle-scene lyrics in Anton, alternating red #ff3830 / white
  • Audio: the original MP3 as-is, no change

What you need before starting

  • The song's MP3 file
  • A lyrics text file — one line per lyric line, in the right order
  • 1–2 photos (artist / portrait) for the particle portrait
  • A Spotify logo PNG (transparent)
  • No paid account for anything — all the tools are free / open-source and local (Python, Node.js and FFmpeg installed)
  • An AI coding agent that can run the pipeline — or basic Python / HTML understanding of your own

One note, and it matters: make the video for your own song, or one you have permission for. Making a video for someone else's released song and monetising it is a different matter — get the rights first.

The copy-paste prompt

This is the prompt to give an AI coding agent. It is real — it describes the pipeline above, and it works.

Take this song MP3, its lyrics (.txt, one line per line) and 2 photos, and build a Spotify-style particle lyric video in 1920×1080 at 60fps. Steps: (1) Separate the vocals with Demucs. (2) Get word-level timestamps with faster-whisper large-v3 and correct the words against my provided lyrics — never show misheard words. (3) Detect tempo, beats and kick hits with librosa. (4) Map the song into 4 looks: a tilted glowing Spotify lyrics card with karaoke word highlighting and spark particles for the opening lines; a monochrome particle portrait made from photo 1 that morphs into photo 2, dancing on the kicks, for the verse; gold Playfair italic motion-graphic lyrics with fast blur word changes for the melodic hook; and a black-and-white rain-on-glass music player for the last line. (5) Build it as a HyperFrames composition driven entirely by the analysis data — no hand-typed timings. (6) Run the checker, snapshot every look, render at 60fps, then verify word sync from the rendered file at 4 timestamps before delivering.

The result

A 54.68-second lyric video, 1920×1080 at 60fps, with the original audio untouched — every word on screen timed to ~0.1 seconds, the particle portrait morphing mid-song, and the gold motion graphics carrying the hook. The reel of it has 5,000 views on Instagram.
