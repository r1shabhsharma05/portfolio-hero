265 Topics to Master AI Engineering (and the 6-Week Order I'd Learn Them In)

265 AI engineering topics from roadmap.sh's AI Engineer (189) and AI Agents (100) roadmaps, deduped, plus the 6-week order to learn them and what to build each week.

You commented topics, so here's the full map. roadmap.sh has two free roadmaps that together cover what an AI engineer actually does in 2026: the AI Engineer roadmap (189 topics) and the AI Agents roadmap (100 topics). I counted every topic in the source repo on 15 November 2026 and merged the ones that appear in both or are the same topic under a different name. That leaves 265 distinct topics, with 660 learning links between them.

Click any box on those two roadmaps and you get a short intro plus free links for that topic. This post is not a copy of the roadmaps (their content stays on roadmap.sh). It's the order I'd go through them in, and what I'd build each week so it sticks.

The short version: don't try to tick off 265 boxes. Learn how LLMs work, then context, retrieval, tools, evals and security, in that order. Build one small thing every week. By week 6 you have a working agent on your GitHub, and that's what gets you the interview.

The 4 I'd start with

  1. Context engineering. What goes into the context window, how to compact it when it fills up, how to keep agents from polluting each other's context, and the ways it fails. Most "the AI is dumb" bugs are context bugs.
  2. MCP. Build one MCP server and one client yourself. Once you've done both, connecting a model to any tool or database stops being magic. Start at modelcontextprotocol.io.
  3. Evals. Deterministic checks, model-graded checks and human review. If you can show how you measured your AI feature, you're ahead of most candidates. DeepEval (~19K ★, Apache-2.0) is an easy place to start.
  4. Agent memory and security. Short-term vs long-term memory, and then prompt injection and tool sandboxing. An agent that can act needs limits on what it can touch.

The 6-week order

Week 1: How LLMs actually work

Tokens, context windows, sampling (temperature, top-p), open vs closed models, and how pricing works per token.

Build: a CLI that sends the same prompt to two models and prints the answer, the tokens used and the cost.

Week 2: Prompting, then context engineering

Few-shot and chain-of-thought prompting, structured outputs, then the bigger idea: managing everything the model sees, not just the prompt.

Build: a summariser for your college notes that returns clean JSON every time.

Week 3: Embeddings, vector databases and RAG

Embeddings, chunking, similarity search, a vector database, and when RAG beats fine-tuning.

Build: "chat with my syllabus": upload PDFs, ask questions, show the source for every answer.

Week 4: Tools, MCP and the agent loop

Function calling, the reason, act, observe loop, and MCP servers and clients.

Build: an MCP server for something you use daily (your calendar, a GitHub repo, a Notion page) and an agent that uses it.

Week 5: Evals and observability

Test sets, model-graded evals, tracing every call, and tracking cost and latency.

Build: 30 test questions for your week 3 app, a score you can re-run after every change, and traces in Langfuse (~37K ★).

Week 6: Security, cost and shipping

Prompt injection, permissions for tools, rate limits, and keeping API keys out of the browser and out of git.

Build: deploy the agent from week 4 with a live link, a README, and one paragraph on how you tested it.

You don't need all 265. You need one deployed agent and the numbers to show it works.

How I'd use this

  • Open the two roadmaps side by side and use this order to decide what to click next.
  • Mark a topic done only when you've used it in code, not when you've watched a video on it.
  • Want to run models locally while you learn? llama.cpp (~135K ★, MIT) just hit v1.0.
  • Post each week's build in public. Six posts, six repos, one story for your interviews.
