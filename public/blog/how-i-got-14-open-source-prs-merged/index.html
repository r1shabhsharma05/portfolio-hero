How I got 14 open-source PRs merged

Rishabh Sharma · 11 November 2026 Draft

I started contributing to open source as a second-year B.Tech student with no internship and no industry connections. Fourteen pull requests later, here is the exact loop that worked.

1. Pick a repo with a real pulse

A repo is worth your time only if a maintainer merged something in the last 30 days, if it has at least 10 actionable unassigned labelled issues, and if its CONTRIBUTING.md does not ban AI-assisted work. I read the full CONTRIBUTING.md first — every time.

2. Reproduce before you fix

Never write a fix for a bug you have not seen fail. Reproduce it, write the smallest change that makes it pass, and verify the behaviour — not just the build.

3. Small is a feature

My merged Jenkins PR fixed one thing. Reviewers merge small, obviously-correct changes; they stall on rewrites. One PR, one fix, one clear description.

4. Answer every review

My first merged Jenkins PR went through two rounds of review. Each comment got a reply and a fix. Silence kills PRs faster than bad code.

Current count: 14 merged, 8 open — Jenkins, WordPress/Gutenberg, and more.
